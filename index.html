REST API: Headers & Session

Every REST call carries a bearer token (Authorization: Bearer …): a long-lived access token created in the interface, or the JWT a login returns. Sessions and tasks belong to that user.

Workflow summary (demo):

  • Create a session: POST /api/v1/sessions (returns session_id).
  • Submit a query: POST /api/v1/sessions/{session_id}/query with body {"prompt":"..."}. You'll receive a task_id and a status_url.
  • Poll task: GET /api/v1/tasks/{task_id} to receive events and the final result when complete.

Capabilities

88 capabilities, organised around the seven principles of the value proposition — read from the framework's own capability pages, so the site says what the documentation says.

  • Agent setup as code

    Everything configured in the interface is reachable through the API.

  • Comprehensive REST API

    Full programmatic control with asynchronous task-based architecture for reliable, scalable automation.

  • Uderia as an MCP Server

    Use any governed Uderia agent as a tool from Claude Desktop, Cursor or another agent.

  • Long-Lived Access Tokens

    Secure automation without session management. Configurable expiration (90 days default, or never); SHA256 hashed storage with audit trail.

  • Apache Airflow Integration

    Production-ready DAG examples for batch query automation. Session reuse via tda_session_id variable; Profile override via tda_profile_id for specialized workloads.

  • n8n Workflow Automation

    Visual node-based workflow builder for enterprise automation.

  • Flowise Integration

    Low-code workflow automation and chatbot development. Pre-built agent flow for TDA Conversation handling; Asynchronous submit & poll pattern implementation.

  • IFOC Workflow - From Ideation to Operationalization

    Four execution modes in one conversation, switched per question with a tag.

  • Session Primer & Automatic Context

    Transform generic LLMs into pre-educated specialists from the first message.

  • Autonomous AI Organization (Genie Mode)

    From intent to autonomy—your AI organization that senses, reasons, and delivers.

  • Intelligent MCP Server Import

    Import community MCP servers in either of two formats. Import from official MCP Registry format (io.example/server-name specifications); Import from Claude Desktop configuration files (direct migration).

  • Docker Deployment Support

    Production-ready containerization. Multi-user support in single shared container; Environment variable overrides.

  • Answer gates

    Before an answer reaches the user it passes the grounding gate (does it stay within the data and knowledge the turn actually had?), the honesty gate (is what it claims about its own evidence true?) and the guardrails (personal data, toxicity, prompt injection, in and out). Per agent, each gate observes, annotates, or enforces — optionally keeping the withheld original for review.

  • Scored after every turn

    A profile-class-aware scorer suite grades each turn, most of it deterministic and at no token cost; the verdicts are signed and bound to the turn they grade.

  • Signed parts, one trust state

    An agent's configuration, knowledge, graphs and skills are each signed; the agent is trusted only when every part it uses is, and a changed part is named.

  • Evidence per answer

    Each answer carries the inventory of what produced it, with each part's signature state at that moment, exportable and verifiable without the deployment.

  • Authority that fails closed

    An agent acts only within the tools, data and writes it was granted; anything else is refused at the chokepoint, not left to the model.

  • The Trust Circle

    Every agent shows where it stands on each station of its trust model and which act is owed next, in one grammar across every surface.

  • Trust travels

    An agent exported as a pack carries its trust posture; the receiving deployment checks it again before it is trusted there.

  • Live Status Panel

    Real-time window into the agent's reasoning process. Strategic plan visualization with phase-by-phase breakdown; Tactical decision display showing tool selection rationale.

  • Sessions & Live Streaming

    Every conversation is one record holding three histories — what the LLM sees, what the UI renders, and the planner's turn trace — written through one serialised seam over file or PostgreSQL storage, with in-process or Redis locks.

  • Asks Instead of Guessing (Needs Input)

    A turn that cannot go on without a person stops and asks — never guesses, never gives up silently.

  • Smart Next Steps

    After each answer, a few one-tap suggestions sit in a dock above the composer — actions such as Chart this or Pin to dashboard, and follow-up questions drawn from your knowledge.

  • The Ontology View

    The sidebar's Ontology is a live, agent-centric map of your whole estate — every agent, what grounds it, what it remembers, and which models, connectors and stores it depends on.

  • A Vote That Teaches

    A thumbs up or down goes through one dispatcher to the part of the agent that produced the answer — the champion plan it reused, the documents it relied on, the expert it routed to, the memory it recalled.

  • Dynamic Capability Discovery

    Instant overview of agent potential. Automatic loading of all MCP Tools from connected servers; Prompt library display with categorization.

  • Every Number Has a Receipt

    Figures in an answer are computed by code, not by the model's own arithmetic. Click any marked number to see the exact rows it came from; a near miss is named rather than passed over.

  • Rich Data Rendering

    Intelligently formats and displays various data types. Query results in interactive tables with sorting/filtering; SQL DDL in syntax-highlighted code blocks.

  • Comprehensive Token Tracking

    Per-turn visibility into LLM consumption. Input token counts for every request; Output token counts for every response.

  • Anti-Hallucination by Architecture

    Ground every answer in verified sources—zero fabrication. Strict retrieval-then-synthesize pattern where the LLM answers only from retrieved documents; Knowledge Graph maps your databases (tables, relationships, business concepts) before query generation.

  • Execution Monitoring (Awareness)

    Cross-source workload tracking. Session roster with status filters and analytics; Per-session execution details: reasoning steps, tool calls with arguments and results, errors.

  • Enterprise Audit Logging - From Uncertainty to Accountability

    Every action recorded, every decision traceable. Complete forensic trail with user, IP, timestamp, and outcome for every interaction; User authentication and authorization events (login attempts, OAuth flows, token generation).

  • Intelligent Context Window Management

    Budget-aware orchestration of every token sent to the LLM. Modular architecture with 13 pluggable context modules (system prompt, tools, history, champion-case reporting, knowledge, knowledge graph, documents, agent memory, review release, findings of earlier turns and more); Five-pass assembly pipeline: resolve → dynamic adjustments → allocate & assemble → surplus reallocation → condense.

  • Interactive Visual Components

    Modular, plugin-based UI component library. Canvas Component: A code and SQL editor in the conversation. It runs queries against your databases, completes table and column names from the Database Navigator, and hands a statement to the agent in one click.; Chart Component: 17 chart types, with the right chart and columns picked from your data automatically.

  • System Customization

    Take control of agent behavior. System prompt editing in Administration → Prompts (Prompt Engineer and Enterprise licences), with per-agent prompt overrides on the agent profile; Save and reset capabilities for experimentation.

  • The Living Answer

    The answer streams in place and never jumps, and notes, evidence and actions sit beneath it in one consistent layout. When it is done, a short receipt shows its steps and one verdict: Verified, N findings or Not checked. Stop it at any time and keep what arrived.

  • Steer & Reattach

    Send a note mid-answer and the agent uses it at its next step. Close the tab and come back: the answer is still running.

  • Regenerate as an Experiment

    A second answer is scored beside the first, so you choose with a reason. Editing a question starts a branch, and nothing is overwritten.

  • The Resilience Envelope

    When a model provider fails, a fallback model you approved takes over and the answer says so. Every recovery is recorded.

  • The Outcome Loop

    A draft with a fixable issue gets one chance to fix it, and is delivered only if the fix passes the same check.

  • Grounded Multimodal

    Uderia reads attachments (images, PDFs, spreadsheets) itself, so their tables can be cited as sources.

  • The Attested Cache

    The stable part of every prompt is cached and paid for once, priced correctly per provider. An unexpected cache miss is reported instead of silently billed. One cache plan serves every provider: the strategic planner marks the stable start of its prompt; Claude (direct, through OpenRouter or on Bedrock) and Amazon Nova get a cache breakpoint there, while OpenAI, Azure and xAI receive each agent's routing key so repeated turns land on a warm cache. An option a provider refuses is learned, never hardcoded.

  • The Governed Tool Surface

    An agent no longer has to read its whole tool catalog every turn. On Relevant per turn it sees the discovery and execution backbone, the framework tools, and the tools the question addresses by its words or comes close to in meaning — with their full descriptions — while the rest wait one TDA_FindTools search away. A tool the agent's authority denies is never offered and never found, and every placement records its reason in the turn record and on the Live Status card. Set it per agent under Data sources → Tools → Tools in context (All enabled tools · Relevant per turn); new Optimize agents start on Relevant per turn.

  • Multi-Source Agents

    One agent can read several sources — more than one MCP server and the Database Navigator's database connections. Each call is routed to the server that holds its data, and every result names the source it came from. When an answer needs rows from two sources together, the model decides what to combine and code decides whether it may: the combine runs as one read-only SELECT over the turn's own results (TDA_Compute op sql), with isolation rules a deployment can tighten per endpoint. Sources are managed in the agent's Data sources section.

    Give a turn a step, token or time budget the agent can see. It paces itself, finishes gracefully, and Continue picks up the rest.

    A library of Teradata SQL patterns, every statement run on a real Teradata before it ships. Agents open only the sections their own database can run.

  • The split, stated plainly

    The public core (uderia-core, Apache 2.0) carries the framework, its runtime and its trust model; the enterprise package (uderia-enterprise, commercially licensed) installs beside it through the plug-in seam and adds nine components (Scheduler, Flow, Dashboard, Canvas, Platform, Explain Plan, OBDA-READ, OBDA-MODEL and OBDA-ACT), identity federation (OIDC, SAML 2.0), scale-out session storage, cloud file stores and external key managers, white-label branding, the Teradata vector store, catalog, deployment backend and SQL patterns, the Google, Microsoft 365 and Slack connectors, the system-prompt editor, and the domain agent packs. The ten components that make and ground an agent (Context Window, Memory, Needs Input, Tool Finder, Skill Library, Compute, Chart, Knowledge Graph, Database Navigator, Files) are public. The system prompts are not part of the split: they are plain text in the public core, and the package adds the editor ().
